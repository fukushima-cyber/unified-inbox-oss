# 招待とログインの操作契約

- 管理者: 利用者のメールアドレスを指定して48時間有効な一回限りの招待コードを発行し、本人へ安全な経路で渡す。コード自体はDBに保存しない。
- 利用者: 初回だけ招待コードと12文字以上のパスワードを入力する。成功すると本人の受信箱を開き、以後はメールアドレスとパスワードでログインする。
- 権限: 招待コードは本人のアカウント作成または同じメールアドレスのパスワード再設定だけに使用する。セッションは本人の会話と連携だけに使え、ログアウトまたは7日経過で失効する。
- 失敗と復旧: 無効・期限切れの招待コード、誤った資格情報、試行回数超過を区別して伝える。パスワード再設定は管理者が新しい招待コードを発行する。ログイン中の作業が認証切れになった場合はダイアログを再表示する。

既存の受信箱を使う判断順に合わせ、ログインと初回設定を一つのモーダルに置いた。入力には常時見えるラベル、ブラウザの入力補助、エラー領域へのフォーカスを使う。[UI Design Dictionary](https://ui-design-dictionary.pages.dev/)のパターン一覧と[デジタル庁デザインシステムのインプットテキスト](https://design.digital.go.jp/dads/components/input-text/)・[モーダルダイアログ](https://design.digital.go.jp/dads/components/modal-dialog/)を確認した。受信箱全体のナビゲーションや色は既存の利用者タスクに合わせて維持し、行政サービスの見た目を模倣しない。招待コードの自動メール送信やパスワードのセルフリセットは現段階では設けない。

## 大きい受信箱

会話一覧と会話内メッセージはそれぞれ50件単位で読み、「さらに会話を表示」「以前のメッセージを表示」で本人が続きを取得する。件数が多い利用者の画面でも初回応答を一定範囲に抑える。[デジタル庁のページナビゲーション](https://design.digital.go.jp/dads/components/page-navigation/)のように前後の位置を明示する方式も検討したが、現段階は新着から過去へ順に追う仕事が主なので追加読み込みを採用した。上限到達時は該当連携に文字でエラーを表示し、管理者への連絡を促す。
