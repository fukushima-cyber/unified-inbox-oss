# 受信箱の操作設計

更新: 2026-10-20

## 利用者と操作

本人が自分のPCで複数の連携先を確認する。日常の操作は「要対応を開く → 相手と本文を読む → 返信先を確かめる → 返信を確定 → 送信結果を確認」。返信先の取り違えと結果不明時の再送は影響が大きい。連携設定と資格情報更新は低頻度なので、通常の会話閲覧から分ける。

| 操作 | 開始条件 | 画面上の完了条件 | 失敗時 |
|---|---|---|---|
| 新着を探す | ローカル起動、または公開構成でログイン済み | 要対応一覧に会話が見える | 同期失敗・履歴不足を上部と連携欄で表示 |
| 会話を探す | 会話が保存済み | サービス、相手・件名・宛先で見つかる | 空結果に絞り込み解除を表示 |
| 返信する | 宛先が確定し連携が有効 | 送信前確認で宛先・本文・添付を見て登録できる | 送信処理中と結果不明を区別し、結果不明は自動再送しない |
| 対応を終える | 会話を確認済み | 要対応から外れる | 失敗した操作は通知し、状態を再取得 |
| 連携を直す | 連携の停止・期限切れ・履歴不足 | 連携欄で状態と操作が見える | 資格情報を再入力できる。同期の欠落可能性は消さない |

## 画面と状態

- 左: 状態別の件数、サービス別の絞り込み。連携・設定は下部で折りたたむ。
- 中央: 会話数と過去7日の受信・返信数、サービス別内訳、データに根拠がある自動化候補を折りたたみ領域に表示する。その下に会話一覧と全履歴を対象とする相手・件名・宛先検索。50件単位の続き読み込みは維持する。本文の全文検索は提供しない。
- 右: 会話と固定した返信先、同期・送信状態、本文、返信欄。スマホ幅では一覧と詳細を切り替える。
- 各サービスの一覧と詳細: 最新の受信メッセージの送り主を表示し、各メッセージにも送り主を表示する。名前を取得できない場合は「取得できませんでした」、IDしかない場合はサービス名付きのIDとして示す。Gmailは件名を明示し、返信先を送り主とは別に示す。
- 空: 未連携なら連携設定へ、検索が空なら絞り込み解除へ案内する。
- 読み込み・失敗: 初回読み込みと会話本文を区別し、初回失敗には再試行を置く。同期停止と履歴不足は会話閲覧中も表示する。
- 送信: 入力内容と選択ファイルは同一画面内で会話ごとに保持する。Gmail・Chatwork・Slackでは添付ファイルを選び、送信前のダイアログでサービス、会話名、返信先、本文、ファイル名を確認する。添付非対応のサービスは理由を示す。送信登録後は処理中と表示し、結果不明の会話では追加送信を止める。
- 自動化候補: 過去7日の同文受信、要対応件数、サービス別受信量から定型返信や通知ルールの候補を提案する。本人のPC内で計算し、メッセージ本文を候補欄へ表示しない。提案を採用する操作や自動送信はまだない。
- 権限: ローカル専用モードはログインなしで所有者の受信箱を表示する。公開構成の未ログイン時はログインダイアログ。鍵やアクセストークンは会話画面に表示しない。

## 参照したパターン

- [UI Design Dictionary](https://ui-design-dictionary.pages.dev/) の List View、Chat UI、Tag / Chip、Empty State、Error Stateを参照。集計は日常の判断に必要な3数値だけを小さく表示し、会話一覧の面積を確保した。
- [デジタル庁デザインシステム](https://design.digital.go.jp/dads/) の[チップラベル](https://design.digital.go.jp/dads/components/chip-label/)、[ノティフィケーションバナー](https://design.digital.go.jp/dads/components/notification-banner/)、[ボタン](https://design.digital.go.jp/dads/components/button/)、[テキストエリア](https://design.digital.go.jp/dads/components/textarea/)を状態表示、重要通知、操作の区別、返信入力に参照。行政サービスの外観は模倣せず、会話を読む密度と長文の視認性に合わせた。
- 色だけで状態を伝えず、「要対応」「送信要確認」「同期が停止」などの文字を付ける。キーボードのフォーカス、見出し、フォームラベル、ライブ通知を備える。
- 選択中の行と通知は色帯を使わず、背景・余白・枠・文字で区別する。会話リスト、詳細、返信欄の内側余白を広げた。

## 検証範囲

基礎レイアウトはサンプルデータのPC幅・390px幅で、一覧、サービス絞り込み、検索、会話詳細、下書き保持、送信前確認、スマホの戻る操作を確認した。今回の色帯・余白・集計の変更はPC幅のダミーデータ画面で確認した。添付ファイル選択のブラウザ自動操作は環境側で失敗したため、画面に添付欄が表示されるところまで確認し、ファイルの送信経路は単体テストで確認した。外部サービスへの添付実送信と変更後の390px表示は未確認。
